# 阻塞项：hello_agents 未安装 + 控制台 GBK 编码，导致 P0 无法做导入验证

## 阻塞1：外部依赖 hello_agents 缺失（阻断级）
- 证据：`python -c "import hello_agents"` → ModuleNotFoundError: No module named 'hello_agents'
- 影响：5 个 py 文件全部 `from hello_agents import ...`（见各文件 1-8 行），因此
  - 全项目无法 import，无法运行 demo.py / 任何端到端测试
  - 原行动计划中 "P0 验证方式：py_compile + import 冒烟测试" 的 **import 部分不可执行**
  - 连带后果：maintainer_report_session_20260927_150631.json 中 commands_executed=0 / issues_found=0，
    注释明细为 "无" —— 即 agent 自身活动几乎为空，与其 147.5s 运行时长不匹配
- 备选验证：仅能退化为语法/AST 级静态检查（py_compile、ast.parse），无法验证运行时行为

## 阻塞2：控制台编码 GBK(cp936)
- 证据：python 打印含 U+1F4C1 等 emoji 的源码行时抛
  `UnicodeEncodeError: 'gbk' codec can't encode character '\U0001f4c1'`
- 影响：源码含大量中文注释与 emoji；直接 print/写入报告用 GBK 会崩溃或被替换为 '?'
  （实测 maintainer_report 与 notes_index 读出后中文全变 '?'）
- 应对：所有读写显式指定 encoding='utf-8'，输出端对 emoji 做 ascii-replace 或设置 PYTHONIOENCODING=utf-8

## 环境事实
- python 3.9.7 (MSC v.1916 64bit)，Windows cmd
- 可用：python / dir / more / sort / find(Windows 版，参数不兼容 Unix) / node
- 不可用：cat / ls / grep / findstr / bash / head / tail(Unix 语义) —— 需全程用 python 代劳
- 父目录 C:\hello-agents\Context 可通过相对路径 `../` 访问（此前"父目录不可达"的判断有误，已更正）
